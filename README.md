# Справочник городского транспорта

Учебный проект по дисциплине «Конструирование программного обеспечения».
Go API читает каталог из PostgreSQL, React показывает маршруты, поиск по номеру
и фильтр по виду транспорта. В каталоге три вымышленных маршрута. Это небольшой
срез для проверки инфраструктуры в ЛР5; администрирование, остановки и расписания
будут реализованы в последующих итерациях.

Задачи и график: [YouTrack SGT](https://vasmaae.youtrack.cloud/issues/SGT).
Предыдущие отчёты находятся в `reports/`.

## Запуск

Нужны Docker Engine и Docker Compose. Скопируйте `.env.example` в `.env`, задайте
свой локальный пароль `POSTGRES_PASSWORD` и выполните:

```sh
docker compose up --build -d
```

Приложение: <http://localhost:8080>. Проверка БД через API:
`curl -f http://localhost:8080/api/health` (успех — HTTP 204).
PostgreSQL и API доступны только внутри сети Compose; наружу на loopback
публикуется web-сервер. Это локальная тестовая среда по HTTP.

`docker compose down` останавливает сервисы и сохраняет данные.
Не добавляйте `-v`, если данные нужны: этот флаг удаляет том БД.

## Разработка и проверки

Нужны Go 1.27, Node.js 24 или новее и отдельная PostgreSQL 18 для тестов.

```sh
make setup
```

Команда устанавливает зависимости и подключает hook проверки сообщений коммитов.
Файлы `package-lock.json` и `go.sum` фиксируют зависимости.

Для локального API задайте `DATABASE_URL` для своей базы и примените начальную
миграцию к **новой пустой** БД:

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/001_catalog.sql
go run ./cmd/api
```

В другом терминале запустите `npm run dev`: Vite перенаправляет `/api` на порт 8080.
Не запускайте локальный API одновременно с Compose на том же порту.

Для полной проверки и сборки задайте `TEST_DATABASE_URL` на выделенную тестовую
БД с той же начальной миграцией и выполните:

```sh
make check
```

Проверяются форматирование Go и JS, `go vet`, ESLint, модульные и интеграционные
тесты, покрытие и сборка. Отчёты и восемь числовых показателей находятся в
`artifacts/`; бинарный API и React-сборка — в `dist/`.
`go test ./...` без переменной запускает только модульные проверки и пропускает
интеграционные; `make test` и CI требуют тестовую БД.

## Структура

- `cmd/api`, `internal/catalog` — запуск API и обработчики HTTP.
- `web` — интерфейс React и его тесты.
- `db` — начальная транзакционная SQL-миграция и учебные данные.
- `deploy`, `compose.yaml` — контейнеры и единый адрес приложения.
- `scripts`, `.githooks`, `.github/workflows` — метрики, правила коммитов и CI.
- `docs` — [правила Git](docs/contributing.md) и [метрики по этапам](docs/quality.md).

Начальная миграция запускается Docker автоматически только для нового тома.
Для существующей БД SQL применяется явно; повторный запуск `001_catalog.sql`
завершится ошибкой и откатит транзакцию. Последующие изменения схемы добавляются
отдельными нумерованными SQL-файлами. Пароли и реальные данные не коммитятся.

## API

- `GET /api/health` — 204 при доступной БД, 503 при ошибке подключения.
- `GET /api/routes?q=1&transport=tram` — JSON-массив маршрутов.
  Параметры необязательны; `transport`: `bus`, `tram`, `trolleybus`.
  Поиск по части номера нечувствителен к регистру; пробелы по краям убираются.
  Неверный вид транспорта или запрос длиннее 40 байт даёт 400, пустой результат — `[]`.

React загружает небольшой каталог целиком и фильтрует его в браузере.
API также поддерживает фильтры и проверяет их независимо от интерфейса.

## Сборки и релизы

CI проверяет каждый push и pull request. После успешных проверок сохраняется
архив `sgt-linux-amd64.tar.gz` с Linux-бинарником, статикой, SQL и документацией.
Для запуска бинарника нужна доступная БД и `DATABASE_URL`; статику следует
раздавать web-сервером с proxy `/api` на API. Для обычного запуска используйте
Compose из исходников.

Тег `v0.1.1` обозначает демонстрационный предварительный релиз ЛР5.
Он не заменяет итоговый `v1.0` по плану на 08.12.2026. Публикация версии запускает
тот же CI; GitHub Release появляется с архивом только после успешных проверок.
