## Локальный запуск браузерных тестов

Используйте выделенную тестовую БД с исходными демонстрационными данными.
Тесты создают и удаляют временные записи. Не направляйте их на пользовательскую БД.

```sh
npx playwright install chromium
make build
export E2E_ADMIN_PASSWORD="$(openssl rand -hex 20)"
export ADMIN_PASSWORD_HASH="$(printf '%s\n' "$E2E_ADMIN_PASSWORD" | go run ./cmd/adminhash)"
npm run test:e2e
unset E2E_ADMIN_PASSWORD ADMIN_PASSWORD_HASH
```

Playwright сам запускает сборку на `127.0.0.1:18081`; `TEST_DATABASE_URL` должен быть
экспортирован. Для отдельного Compose с тестовыми данными можно задать `E2E_URL`.
Сценарии идут последовательно, поскольку работают с одной БД и одним администратором.

## Отчёты

Локально: `artifacts/`. В GitHub: **Actions → CI → запуск → Summary → Artifacts**.
В Summary отображаются метрики Go и Vitest и отдельный итог Playwright. Артефакт
`quality-…` хранится один день и содержит:

- `go-tests.jsonl`, `go-coverage.txt` и `go-coverage.out` — Go и PostgreSQL;
- `web-tests.json` и `web-coverage/` — Vitest; проценты относятся к `App.jsx`;
- `playwright-html/index.html`, `playwright.xml`, `playwright.json` — браузер;
- `playwright-results/` — следы и снимки при сбоях;
- `metrics.json`, `metrics.md` и `eslint.json` — сводка и статический анализ.

Отчёт Playwright можно открыть через `npx playwright show-report artifacts/playwright-html`.
Браузерный счётчик не смешивается с историческими метриками ЛР5.
Технические основания: [Playwright CI](https://playwright.dev/docs/ci) и
[защита от межсайтовых запросов Go](https://pkg.go.dev/net/http#CrossOriginProtection).
