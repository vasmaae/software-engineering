# Метрики качества по этапам разработки

CI собирает метрики при каждом push и PR, а при завершении этапа фиксируется
отдельный снимок с ID этапа, фактическим временем, SHA коммита и URL запуска.
Даты ниже взяты из плана ЛР3; это план, а не утверждение о фактической сдаче.

| Этап YouTrack | Результат                  | Плановая сдача 2026 года |
| ------------- | -------------------------- | ------------------------ |
| SGT-14        | Прототип интерфейса        | 26 сентября              |
| SGT-15        | Инфраструктура             | 3 октября                |
| SGT-16        | Данные и администрирование | 24 октября               |
| SGT-17        | Публичный справочник       | 14 ноября                |
| SGT-18        | Расписания и адаптация     | 28 ноября                |
| SGT-19        | Итоговое тестирование      | 5 декабря                |
| SGT-20        | Релиз и итоговая сдача     | 8 декабря                |

Замеры не восстанавливаются задним числом. Для уже прошедшего планового срока
фиксируется фактическая дата запуска. Снимок инфраструктуры ЛР5 не подменяет
снимки будущих итераций и итогового релиза.

## Получение снимка

После проверки критериев этапа поставить аннотированный тег на соответствующую
версию `main`, например:

```sh
git tag -a stage/SGT-15 -m 'SGT-15 infrastructure metrics'
git push origin stage/SGT-15
```

CI автоматически определяет ID из тега и сохраняет `metrics.json`, `metrics.md`,
исходные отчёты тестов и покрытия в артефакт `quality-current-<номер запуска>`.
Тег сохраняет точную версию исходников. Альтернатива: Actions → CI → Run workflow,
выбрать ветку/тег и поле `stage`. Завершённый этап привязывается к проверенной
версии, а не к произвольному последнему коммиту.
Для повторного замера того же этапа используйте Run workflow; опубликованный тег
не передвигайте.

Артефакты CI с отчётами и сборкой хранятся один день. При частичной сдаче скачать снимок и сохранить его
в `docs/measurements/<этап>/` через отдельный PR; добавить ссылки на запуск и
снимок в описание карточки YouTrack. Это сохраняет историю и после истечения
срока артефактов. Для будущих этапов снимки пока отсутствуют.

Фактический [замер SGT-15 от 22.10.2026](measurements/SGT-15/README.md) сохранён
вместе с исходными отчётами. Его версия совпадает с релизом `v0.1.1`.

## Показатели

| Поле                        | Что измеряется                                              | Источник              |
| --------------------------- | ----------------------------------------------------------- | --------------------- |
| `eslint_errors`             | Ошибки статического анализа JS/JSX                          | ESLint JSON           |
| `eslint_warnings`           | Предупреждения JS/JSX                                       | ESLint JSON           |
| `go_statement_coverage_pct` | Покрытие операторов пакетов `internal`                      | Go cover              |
| `web_line_coverage_pct`     | Покрытие строк React-компонента                             | Vitest V8             |
| `web_branch_coverage_pct`   | Покрытие ветвлений React-компонента                         | Vitest V8             |
| `tests_passed`              | Успешные конечные тесты Go и тесты React                    | Go JSON и Vitest JSON |
| `tests_failed`              | Упавшие конечные тесты Go и тесты React                     | Go JSON и Vitest JSON |
| `test_execution_seconds`    | Сумма времени выполнения Go-пакетов и тестовых файлов React | Отчёты test runner    |

Это восемь числовых полей из предложенных в задании показателей. Время тестов
не включает установку зависимостей и сборку и не является временем всего CI.
Родительские Go-тесты с subtest не считаются повторно. Тесты самого сборщика
метрик выполняются отдельно и не входят в показатели приложения.

Go-тесты запускаются с `-count=1`: результаты интеграционных тестов не берутся
из кеша, поскольку состояние внешней PostgreSQL не входит в ключ кеша Go.

Веб-покрытие относится к `App.jsx`, Go-покрытие — к `internal`, без точки входа
`main`. Эти проценты нельзя выдавать за покрытие всего будущего приложения.
`gofmt`, `go vet` и Prettier являются дополнительными обязательными проверками.

## Условия успешного CI

Нулевые ошибки/предупреждения ESLint, корректное форматирование, успешный
`go vet`, допустимое имя ветки, корректные сообщения всех новых коммитов и
заголовок PR по Conventional Commits, успешные тесты (включая
PostgreSQL), покрытие React не ниже 80% строк и ветвлений, успешная сборка.
Числовой порог Go-покрытия пока не вводится; фактическое значение сохраняется.

Пропущенный отчёт считается ошибкой сбора, а не нулём. Сборщик имеет проверки
на двойной подсчёт вложенных тестов и отсутствие покрытия.

Автоматическое развёртывание на внешнем сервере в ЛР5 не включено. Для проверки
приложения используется локальная тестовая среда Docker Compose.

Технические основания: [защита веток GitHub](https://docs.github.com/en/rest/branches/branch-protection),
[GitHub Flow](https://docs.github.com/en/get-started/using-github/github-flow),
[Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/),
[Vite](https://vite.dev/guide/).
